# Hand-off to the GDD session: great projects (đại công trình)

> **From:** the UI / map session, 2026-11-23. **To:** whichever session owns `design/gdd/*`.
> **User's pick (2026-11-23):** the levers and their sizes go into a GDD revision by the GDD session, with the user.
> This session does not edit `design/gdd/*`.

**Read:** `design/world/great_projects_proposal.md` (10 projects, where they go, what lever each moves, how each stage
looks; user's answers at its end). Art for one example place per project is done
(`assets/map/places/stages/manifest.json`, kinds = project keys).

**What the GDDs would need (a suggestion; the GDD session and the user decide):**
1. `design/gdd/travel-map.md` rule 31 (shared works, layer 2): great projects as named, staged shared works; a project's
   stages are a **list of any length** (today 2-5; mostly 3-4); each finished stage moves a lever the game already has
   (density, element share, production, development level, residence grade cap, travel time, beast-tide defence);
   setbacks (war, beast tide: back one stage) and fading of abandoned upkept works (rule 31's two kinds).
2. `design/gdd/sects.md` (investment, Formula F3): NPC holders choose and fund projects from a treasury's surplus;
   which place kinds may start which project (the proposal's "Where" column).
3. The player: **funds** a holder's project through a sect or city mission first; **builds on own ground later**
   (`design/gdd/cave-abode.md`, once cave abode land is bigger).
4. Numbers: cost per stage, seasons per stage, effect size per stage, upkeep: none set yet (Tuning Knobs).
5. Presentation (for this session to build once rules exist): the stage art swaps the place's sprite on the near map; a
   small inked symbol per project kind beside the place name on the far map once complete.

**Data hook already in the game:** none yet. Places have no level or project state in the game data; the stage art
waits for it.
